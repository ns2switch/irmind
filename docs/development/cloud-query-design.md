# Cloud query design after the MVP

This page is for maintainers designing source-side cloud queries. It specifies no runtime feature yet. The MVP reads S3, GCS, and Azure Blob objects and builds a local Parquet store; cloud query engines follow after that work and its custody review.

## Shared contract

`CloudQueryPort` will be an async, cancelable application port. Its single `execute(AuthorizedCall, CancellationToken)` entry point will accept either an estimate request or an execution request and return typed estimate, progress, and result events. The domain will validate an immutable `CloudQuery` before authorization: trusted source and table identifiers selected from configuration, an allowlisted field, `eq`/`not_eq`/`prefix` operators, a UTC interval inside the case and organization scope, `events`/`count_by`/`top`/`distinct` aggregation, and a bounded row count. Values are parameters or escaped literals produced by the adapter. The model never supplies SQL, KQL, dataset paths, workgroup names, or result destinations.

The estimate and execution are separate authorized calls through the same module registry and audit path. An estimate does not grant permission to run. The analyst sees the compiled source, exact structured predicate, estimated scan, maximum allowed scan, and current per-case budget before any billable execution. If an engine cannot give a trustworthy preflight estimate, execution requires signed analyst approval or is denied by the configured ceiling. Every run has a server-side time limit, response-size limit, cancellation, and a per-case scan budget. The adapter reports actual scanned bytes when available; budget accounting is conservative when a query is canceled or metrics lag.

Every result becomes original local evidence through the existing guarded, signed result path. The signed metadata includes the provider query or job ID, engine, trusted table identifier, bounded request, execution time, result hash, and reported scan/cost units. A result preview is redacted before reaching the model or TUI. Diagnostic tracing never includes query values, evidence, URLs with credentials, or results.

## Engines and minimum authority

| Engine | Source and translation | Estimate and hard limit | Minimum authority and material risk |
| --- | --- | --- | --- |
| Athena | Approved CloudTrail and Security Lake tables over S3; compile the structured predicate to a `SELECT` with fixed table and partition filters. | A separate estimate is not assumed. Use catalog partition sizes as a conservative bound when available and an Athena workgroup per-query data-scanned control; canceled queries can still incur charges. | Dedicated workgroup; `athena:StartQueryExecution`, `GetQueryExecution`, `GetQueryResults`, `StopQueryExecution`, read access to the relevant Glue/Lake Formation metadata and source S3 objects. Prefer Athena-managed results to avoid client write access to a result bucket. If unavailable, use one tightly scoped results bucket and acknowledge the necessary write permission. This is a billable query job, not a pure read-only API. |
| CloudTrail Lake | Approved event data stores and account/time filters; compile the same query model to a restricted SQL subset. AWS stopped opening CloudTrail Lake to new customers after May 31, 2026, so this adapter is relevant only to existing users. | Apply the case budget to the selected store and time range; if reliable pre-execution byte estimation is unavailable, require analyst approval. | `cloudtrail:StartQuery`, `DescribeQuery`, `GetQueryResults`, and `CancelQuery` on approved event data stores. Long-running jobs and billable scans are the main risks. |
| Security Lake | Query its approved Athena/Glue tables through the Athena adapter with OCSF field mapping. | Athena workgroup scan control plus a conservative local estimate. | Lake Formation grants, source S3 reads, and the same restricted Athena job and result location. Schema version and partition mapping must be pinned. |
| BigQuery on GCS | Approved external tables and datasets only; use the structured query model and bind values as parameters. | Dry run first, then set `maximumBytesBilled` on the execution job. Treat a zero-byte or lower-bound dry-run estimate for an external table as unknown, not free. | `bigquery.jobs.create`, job read permissions, dataset/table read access, and GCS object read access where the table requires it. Query jobs create billable work; external-table reads may incur storage and transfer costs. |
| Cloud Logging Log Analytics | Approved log bucket or linked BigQuery dataset with a fixed table/view mapping. | Query only an explicit UTC interval; if no reliable estimate exists, ask the analyst before execution. | Logging view access or dataset read plus BigQuery job authority where linked datasets are used. A linked dataset can expose all its views to a grantee, so grant and scope must be reviewed. |
| Azure Data Explorer | Approved external tables over Blob; compile a bounded KQL expression from typed operators and fixed table names. | Partition pruning and file metadata can bound a local estimate, but a missing bound requires approval. Enforce server timeout and row cap. | Viewer on the approved ADX database and access to the external storage through a declared identity. External-table scans and storage reads incur cost. No SAS token appears in query text or configuration. |
| Azure Log Analytics | Approved workspaces and tables only; compile bounded KQL and pass a separate timespan. | No dependable dry run is assumed. Use a conservative configured ceiling, analyst approval when unknown, API timeout and result limits. | Log Analytics Reader or the narrower workspace/table query permissions needed for the selected tables. Cross-workspace queries are disabled unless each workspace is in scope. |

## Threats and tests before implementation

- Identifier and field injection: catalog identifiers come from reviewed configuration, never model arguments; values are bound or escaped by the provider adapter. Test adversarial Unicode, quotes, separators, comments, nested expressions, and attempted result redirection.
- Scope bypass: both the domain policy and the remote query enforce account/project/subscription, source, table, and UTC bounds. A changed policy ceiling invalidates pending approvals. Test every engine translation against a fake server.
- Cost surprise: an estimate may be absent or too low. Server-side limits take precedence where available; otherwise approval is mandatory and the case budget is updated from the highest defensible scan measure. Test estimate/run mismatch and canceled jobs.
- Credential exposure and side effects: use only the explicitly configured secret backend; disable redirects and raw query logging. Prefer Athena-managed results; if customer-managed output is necessary, restrict and clean its location. No query may mutate source data.
- Custody: record the job ID and returned bytes as signed evidence; a partial or failed job cannot be presented as a complete result. Test replay and altered result bytes.
